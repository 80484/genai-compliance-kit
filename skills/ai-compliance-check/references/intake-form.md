# 采集清单（Intake Form）

> 目的：用最少的提问拿到足够判定的事实。
> 原则：**问什么取决于角色**，先问 Q1–Q5 定位，再按角色深挖。

---

## 第一组 · 定位（必问）

| # | 问题 | 为什么要问 |
|---|---|---|
| Q1 | 产品叫什么？一句话说明它做什么？ | 报告标题与范围 |
| Q2 | 用户在哪里？仅中国境内 / 境外也有 / 仅境外 | 决定《暂行办法》是否适用 |
| Q3 | 用户怎么访问？App / 网页 / 小程序 / API / 内嵌在别人产品里 | 决定分发平台义务、备案公示位置 |
| Q4 | 模型从哪来？自研 / 调第三方 API / 开源模型微调 / 混合 | 决定 A 还是 B |
| Q5 | 用户可以发布内容给别人看吗？（评论、作品广场、分享链接） | 决定是否叠加 C |

> Q2 答"仅境外"→ 直接出不适用的说明，不要继续问。
> Q4 答"自研"→ 触发 A 类（训练数据域）。
> Q5 答"是"→ 叠加 C 类（传播平台核验义务）。

---

## 第二组 · 能力与模态（必问）

| # | 问题 |
|---|---|
| Q6 | 生成哪些内容？文本 / 图片 / 音频 / 视频 / 虚拟场景（多选） |
| Q7 | 内容能导出吗？下载 / 复制 / 分享到站外 |
| Q8 | 有没有以下功能：人脸生成或替换、声音克隆或仿声、姿态操控、一键换脸 |
| Q9 | 是否面向未成年人开放？有没有年龄门槛 |

> Q6 决定显式标识要验哪几种模态。
> Q7 决定"导出链路标识"这条必查。
> Q8 命中任一项 → 触发深度合成的高风险条款（生物识别编辑），需单独提示。
> Q9 决定未成年人保护条的判定强度。

## 第五组 · 条件触发（视情况问）

- 有境外主体或外资股东 → 外资准入（《暂行办法》第 23 条）
- 训练或运营涉及数据出境 → 数据出境合规
- 涉及新闻、出版、影视、医疗、金融等特殊行业 → 行业前置审批
- 提供人脸/人声编辑 → 单独同意与安全评估（深度合成第 14、15 条）

---

## 材料收集的最小集合

判定要落地，至少要拿到：

1. 产品说明或 PRD（一页即可）
2. 用户协议 + 隐私政策文本
3. 备案编号（如有）与公示页截图
4. 生成内容样本：各模态各一份，**含导出后的文件**
5. 内容安全策略说明（一页即可）
6. 数据来源清单（A 类）

**缺第 4 项时，标识类检查项一律判「待核」，不许判「符合」。**

---

## 提问方式建议

不要一次抛 19 个问题。按三段走：

1. 先问 Q1–Q5，拿到角色结论（30 秒）
2. 按角色给出"接下来需要你提供 X、Y、Z"，让对方一次性准备
3. 材料到手后只追问缺口

对创业者/非法律背景的人，把术语换成白话：

- "算法备案" → "在网信办系统里登记你的算法，拿到一个编号"
- "隐式标识" → "文件属性里写一句'这是 AI 生成的'，别人用工具能读到"
